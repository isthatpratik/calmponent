## Usage

```tsx
<Timeline>
  <TimelineItem status="done" title="Build" time="09:41:11" duration="31s" />
  <TimelineItem status="running" title="Deploy" time="09:41:42" />
  <TimelineItem status="pending" title="Verify" />
</Timeline>
```

## Parts

- `Timeline`: an ordered list. Takes `loading` (skeleton rows shaped like items), `loadingRows` (default `3`), and `empty` (shown when there are no items).
- `TimelineItem`: takes `status` (`"done"`, `"running"`, `"pending"`, `"failed"`, or `"skipped"`), `title`, `description`, `time`, and `duration`. In proportional mode, also `seconds` and `previousSeconds`.
- `Timeline proportional`: draws each rail as long as its step took (`pxPerSecond`, default `4`, capped at 160px), with a ghost of `previousSeconds` and a "was 31s" note.
- `TimelineGroup`: a phase, such as Build, with a `label` and a `total`.
- `TimelineHeader`: a `title`, mono `meta` such as author and commit, and a `total`.
- `TimelineBar`: the run as one bar. Each segment (`{ id, label, seconds, group, status }`) is as wide as it took. Phases differ by gray step; a failed segment is red, and a running one breathes. Segments grow in from the left, and one tooltip glides between them.

## Accessibility

- The timeline is an ordered list, so screen readers announce the number of steps.
- Each item adds its status as hidden text, for example "Build, Done", so color is never the only signal.
- The running item has `aria-current="step"`.
- With reduced motion, the line fills without drawing, icons appear without popping, and the skeleton does not pulse.
